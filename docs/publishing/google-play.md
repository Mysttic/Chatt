# Google Play

Everything worth having at hand while filling in the Play Console, so it can be
done in one pass. The graphics are generated by `app/tool/store_assets.py` into
`docs/publishing/assets/google-play/`.

## Before you start: the account

- **An account created after 13 November 2023** has to go through a **closed
  test: at least 20 testers over 14 consecutive days** before it gets
  production access. Older accounts do not. Check in the console whether the
  app shows an "Apply for production access" requirement.
- Play accepts only an **AAB** (App Bundle), not an APK. The release workflow
  builds an AAB next to the APK, signed with the same key.
- **Play App Signing**: on the first upload our key from `chatt-release.jks`
  becomes the *upload* key and Google creates a separate signing key. That is a
  good thing: a lost upload key can be reset through Google support, a lost
  signing key cannot.
- Target API 36 satisfies the "no more than a year behind the latest"
  requirement.

Emulator screenshots are 1280x2856 (a ratio of 2.23), so the script scales them
to a height of 1920 and pads the sides out to 1080x1920 (9:16). A separate set
per language, because Play shows the listing in the user's language.

## Console questionnaires

| Questionnaire | Answer |
|---|---|
| Privacy policy | the URL of `privacy-policy.md` (once the repository is public: GitHub Pages or raw.githubusercontent.com) |
| App access | every feature works without signing in |
| Ads | contains no ads |
| Content rating (IARC) | a messenger; users exchange content with each other; no content from the app |
| Target audience | 18+ (simplest; the app is not for children) |
| Data safety | **collects and shares no data**; data encrypted in transit: yes; the user can delete data: yes (locally) |
| Government, health, finance apps | no |

For "Data safety" what counts is Google's definition: "collected" means sent
off the device to the developer or to a service. Messages go to the user's
other device, not to us, so the answer "does not collect" is truthful. It is
worth writing that in the description field.

## Automating uploads

After the first manual upload (Play requires the first version to come in
through the console), later ones can go from a workflow:

1. In Google Cloud, a service account with access to the Play Console (the
   "Release manager" role for this app) and a JSON key.
2. A repository secret, `PLAY_SERVICE_ACCOUNT_JSON`.
3. A step in `wydanie.yml` after the AAB is built, for example
   `r0adkll/upload-google-play@v1` with `track: internal` (or `closed`) and
   `releaseFiles: app/build/app/outputs/bundle/release/app-release.aab`.

The internal, closed and production path is walked in the console, so the
automation uploads to `internal` and the promotion stays a click.
