# Microsoft Store

Everything worth having at hand in Partner Center. The graphics are generated
by `app/tool/store_assets.py` into `docs/publishing/assets/microsoft-store/`.

## Why the Store when there is an installer

The Store **signs the package itself**. That takes care of the SmartScreen
warning everyone gets today when they download the installer from GitHub,
without buying a code-signing certificate. On top of that, updates arrive by
themselves and uninstalling is clean.

## Before you start: the account and the package identity

1. In Partner Center: **Apps and games, New product, MSIX or PWA app**, and
   reserve the name "Chatt" (check that it is free).
2. From the **Product identity** tab, copy three values:
   - `Package/Identity/Name` (for example `12345Mysttic.Chatt`),
   - `Package/Identity/Publisher` (in the form `CN=xxxxxxxx-xxxx-...`),
   - `Package/Properties/PublisherDisplayName`.
3. Enter them as **repository variables** on GitHub (Settings, Secrets and
   variables, Actions, Variables): `MSIX_IDENTITY_NAME`, `MSIX_PUBLISHER`,
   `MSIX_PUBLISHER_DISPLAY_NAME`. The "MSIX" step in the release workflow
   builds the package only when they are set; without them a release goes as
   before.

The Store package is **unsigned** (`--store`); the Store adds the signature.

## What behaves differently in MSIX than in the installer

To check on the first package, before it goes to certification:

- **Autostart.** The app creates an entry in `HKCU\...\Run`, and MSIX
  virtualises registry writes, so the entry lands in the package container and
  Windows never sees it. The package needs a `StartupTask` declaration in the
  manifest (the `msix` package has a `startup_task` option for it), and the
  switch in settings then has to call the `StartupTask` API instead of the
  registry. Until that is done, the switch in the Store build will not work and
  has to be hidden there.
- **Network.** The manifest has to declare `internetClient`,
  `internetClientServer` and `privateNetworkClientServer`. Without the last
  one, a server listening on the local network will not accept connections.
- **Firewall.** A Store package gets its own firewall rule, so the system asks
  again on the first start.
- **DPAPI, the tray, files in Documents** work unchanged (the app is "full
  trust").

## The store listing

The Store has a single description field (up to 10 000 characters), with no
separate short description. The text is the same as for Google Play
([google-play.md](google-play.md), the "Full description" section), with one
change in the last paragraph:

- EN: `Chatt needs another device running Chatt on the same Wi-Fi: an Android phone or another Windows PC.`
- PL: `Chatt potrzebuje drugiego urządzenia z Chattem w tej samej sieci Wi-Fi: telefonu z Androidem albo innego komputera z Windows.`

The fields:

| Field | Value |
|---|---|
| Category | Social |
| Subcategory | none |
| Product features (up to 20 bullets) | the first seven headings from the full description, as short sentences |
| Keywords (up to 7) | see [positioning.md](positioning.md), one set per language |
| Privacy policy | the URL of `privacy-policy.md` |
| Support page | the repository address (once it is public) |
| Age rating | the IARC questionnaire, the same as for Play |

## Graphics

| Item | Size | Source |
|---|---|---|
| Store logo (1:1) | 1080x1080, PNG | `assets/microsoft-store/logo-1080.png` |
| Desktop screenshots | at least one, **min. 1366x768**, PNG | `assets/microsoft-store/zrzuty/{pl,en}/` |
| Icons inside the package (Square44, Square150, Wide310, StoreLogo and so on) | generated by the `msix` package from one icon | automatic |

The desktop screenshots come from `app/tool/windows_shots.dart`: it brings up a
separate instance of the app with an empty profile, adds a demonstration
conversation to it and captures the window alone at 1600x900. That way there
are no private conversations in the screenshots.

## Certification: what the Store checks

- The app starts and works without the internet: it does.
- It does not fall over on the first start under a clean account: check the
  package on a clean user profile.
- Every feature in the description is available: we promise nothing beyond what
  is there.
- The privacy policy is at a working address.
- If the app listens on the network, the description has to say so: it does.

## Automation

The Microsoft Store Developer CLI (`msstore`) can upload a package and create a
submission. What it needs:

1. An Azure AD application with access to Partner Center (tenant id, client id,
   client secret). Instructions are in Partner Center, Account settings, User
   management, Azure AD applications.
2. Repository secrets: `MSSTORE_TENANT_ID`, `MSSTORE_CLIENT_ID`,
   `MSSTORE_CLIENT_SECRET`, plus `MSSTORE_SELLER_ID`.
3. In the workflow: `microsoft/setup-msstore-cli`, then
   `msstore publish <path.msix> --appId <the Store id>`.

The first submission, with the listing, the graphics and the questionnaires, is
done by hand in Partner Center; the automation swaps the package in later ones.
